# Паспорт Conversation Service

## Ответственность

- состояние диалога;
- идемпотентность входящего сообщения;
- вызов Agent Runtime;
- создание сохранённого действия через Action Service;
- ответ с текстом, карточкой подключения или карточкой подтверждения;
- проверка подключения перед созданием действия внешнего connector.

## Не входит в ответственность

- протокол Telegram, VK или Web;
- разбор текста моделью;
- выполнение action и проверка payload hash;
- вызов MCP;
- отображение карточки.
- хранение OAuth state, code и token.

## Текущее состояние

Подготовлены generated API `3.1.0`, PostgreSQL-схема и jOOQ repositories. Повтор сообщения с тем же
`requestKey` не создаёт дубль. Исходный текст стирается при закрытии диалога и после 24 часов.
Атомарный lease не даёт двум worker одновременно обрабатывать сообщение; зависшая работа доступна для
повтора через две минуты.

Application-сценарий уже связывает хранение, lease, Agent, Action и построение карточки. Для
`calendar.create_event` карточка строится из payload, сохранённого Action Service, а не из временного
ответа Agent. Повтор готового обычного сообщения возвращает сохранённый ответ без сетевых вызовов.
Для карточки подключения сервис получает новую короткоживущую ссылку у Connection Service и не
сохраняет её.

HTTP endpoint и HTTP-адаптеры Agent Runtime, Action Service и Connection Service реализованы по
контрактам `3.1.0`. Bearer token пользователя передаётся сервисам, а `tenant_id` и `sub` берутся только
из проверенного JWT. Google Calendar выбирается через стратегию connector, а не через цепочку `if`.
