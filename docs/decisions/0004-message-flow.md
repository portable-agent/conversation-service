# ADR-0004: Оркестрация сообщения вне транзакции

- Status: accepted
- Date: 2026-09-16

## Решение

`MessageFlowService` выполняет один application-сценарий: сохраняет вход, получает короткий lease,
обращается к Agent Runtime, при полном предложении сохраняет действие через Action Service и строит
ответ через стратегию карточки. Уточняющий вопрос возвращается как текст без создания действия.

Agent и Action объявлены внутренними Java-портами. Их HTTP-адаптеры и generated contract types будут
добавлены отдельно. Сам flow не является транзакционным: каждая операция базы уже выполняется своей
короткой транзакцией.

Повтор с готовым ответом не вызывает внешние сервисы. Ошибка внешнего сервиса сохраняется только как
безопасный `WorkError`; текст exception и личные данные не сохраняются. Карточка строится из payload,
который вернул Action Service после сохранения, вместе с его `payloadHash`.

## Причина

Такой application-слой можно проверить быстрыми unit-тестами и подключить к HTTP без смешивания
сетевых DTO, бизнесового сценария и SQL. Отсутствие общей транзакции во время HTTP-вызовов защищает пул
соединений, а lease и идемпотентность Action Service обеспечивают безопасный повтор.
